# 프로그래머스 12906. 같은 숫자는 싫어 - 코드 리뷰

## 코드 분석

현재 코드는 `arr[i]`와 `arr[i+1]`을 비교해서 연속된 중복을 제거하려는 방식입니다.

```javascript
function solution(arr) {
    var answer = [];
    for(let i = 0; i < arr.length; i++) { 
        if(arr[i] !== arr[i+1]) answer.push(arr[i])
    }
    return answer;
}
```

동작은 얼핏 맞지만, 마지막 원소 처리가 `arr[i+1]`이 `undefined`가 되는 것에 의존하고 있습니다. 이는 우연히 잘 동작하지만 가독성이 떨어지고 잠재적인 버그 가능성이 있습니다.

## 개선할 부분

1. **마지막 원소 처리**: 현재 방식은 `arr[arr.length-1] !== undefined`에 의존해서 마지막 원소를 처리합니다. 이는 우연히 작동하지만 직관적이지 않습니다.

2. **의도의 명확성**: 지금 조건은 "다음 값과 다르면 push"이지만, 실제 의도는 "현재 값이 이전에 넣은 값과 다르면 push"가 더 직관적입니다.

3. **변수명**: `answer`보다 `result`나 `filtered` 같은 이름이 더 직관적일 수 있습니다.

4. **경계 조건**: 빈 배열이나 단일 원소 배열에 대한 명시적 처리는 없지만 현재 코드로도 잘 동작합니다.

## 성능 및 시간복잡도

- **시간복잡도**: O(n) - 배열을 한 번 순회하므로 효율적입니다.
- **공간복잡도**: O(k) - k는 중복 제거 후 남은 원소 개수입니다.

전반적으로 문제를 잘 해결했지만, 코드의 가독성과 의도 표현에서 개선할 여지가 있습니다.
